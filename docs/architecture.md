# SJTU 课程下载器 — 架构设计与机制原理

本文档详细阐述 SJTU 课程下载器的内部技术架构、下载引擎算法、分片直传机制与系统级安全隔离模型，供深入了解内部实现及二次开发参考。

---

## 1. 总体架构与模块分层

应用基于 Electron + React 19 + TypeScript 构建，严格遵循主进程与渲染进程的上下文隔离规范。

```
┌─────────────────────────────────────────────────────────────┐
│                   渲染端 (Renderer / React 19)               │
│  - 状态管理: Zustand (持久化、微任务批处理、聚合统计)         │
│  - 课程探索: NetdiskCourseExplorer (分栏/列表/网格三重视图)   │
│  - 云盘管理: CloudPanExplorer (CRUD、上传、下载、面包屑)     │
│  - 认证与设置: Login.tsx (Webview 注入、多账号切换)、Settings│
└──────────────────────────────┬──────────────────────────────┘
                               │ contextBridge (window.api)
┌──────────────────────────────▼──────────────────────────────┐
│                    预加载层 (Preload / IPC Bridge)          │
│  - 严格通道白名单映射，杜绝向渲染进程泄漏 Node.js 原生句柄   │
└──────────────────────────────┬──────────────────────────────┘
                               │ IPC invoke / handle / on
┌──────────────────────────────▼──────────────────────────────┐
│                    主进程 (Main Process / Node.js)          │
│  - 下载调度引擎: 动态多线程并发、惰性任务物化、断点续传       │
│  - 云盘传输引擎: 腾讯 COS 4MB 分片流式直传、Abort 控制       │
│  - 凭据安全保险库: Electron safeStorage (DPAPI/Keychain)    │
│  - 业务编排器: Canvas / v.sjtu / 好大学在线 (LTI/OIDC/API) │
└─────────────────────────────────────────────────────────────┘
```

## 2. 下载引擎调度算法与性能优化

### 2.1 动态并发控制与网络健康监测 (Concurrency & Network Health)

系统采用兼顾性能与稳定性的动态并发调度与网络健康监控机制：
1. **全局可调并发预算**：用户可在「设置」面板自由设定 1 ~ 16 线程（默认 3 线程），HLS 视频多流切片下载与普通文件流共享并发配额；
2. **实时平滑流速监控 (EMA)**：主进程按秒采用指数移动平均算法（EMA，平滑系数 0.6:0.4）平滑计算上下行实时吞吐速率并推送至顶栏展示；
3. **网络健康与断网熔断恢复**：实时识别 DNS 解析故障（`ENOTFOUND`）与连续网络异常；当连续失败触发熔断时自动阻断新任务出队，并启动 30 秒退避恢复定时器，网络连通后自动重启队列调度。

### 2.2 惰性任务物化 (Lazy Task Materialization)
当用户批量勾选数百个文件加入下载时，系统仅将任务描述规范（`DownloadTaskSpec`）存入等待队列，只有当调度器分配到空闲并发槽位时，才真正物化实例化下载运行时对象（`TaskRuntime`）。内存占用严格控制在 $O(\text{并发数})$ 级别，而非 $O(\text{总文件数})$。

### 2.3 裸 Node.js HTTPS 引擎与会话注入
- **绕开 Chromium 渲染栈限制**：Chromium 对跨域 CDN 请求容易触发 `BLOCKED_BY_CLIENT`。下载引擎直接使用 `node:https` 发起流式网络请求，手动跟随 302 重定向并处理 Range 断点续传；
- **Cookie 安全隔离传递**：Canvas 课件直链解析时，仅在请求 `oc.sjtu.edu.cn` 时从 Electron Session 提取并注入凭据 Cookie；一旦 302 重定向至 S3 预签名直链，立即剥离 Cookie，杜绝凭据向第三方域泄漏。

## 3. 交大云盘 SMH 与 COS 分片直传

交大云盘后端基于腾讯云对象存储（COS）与微服务架构。客户端实现了全流程边下边传的流式直传管道：

1. **逐级目录路径缓存**：在创建多级目录时维护内存树状缓存，避免重复发起深层目录创建请求；
2. **4MB 分片流式上传**：大文件切分为 4MB 块流式上传，断点续传状态保存在 `UploadSessionState` 中；
3. **即时请求熔断 (Abort)**：通过暴露底层 `ClientRequest`，当用户点击「暂停」或「取消」时，立即物理中止正在传输的分片网络连接，杜绝出现“点了暂停后台还在传”的幽灵流量。

## 4. 凭据安全保险库 (Credentials Vault)

针对统一身份认证（jAccount）账密本地化存储，系统设计了高安全级别的硬件绑定加密保险库：

1. **操作系统原生硬件级加密**：
   - Windows 平台：调用底层 Windows DPAPI (`CryptProtectData`)，秘钥绑定当前 Windows 登录用户与本地机器硬件；
   - macOS 平台：无缝接入系统 Keychain；
2. **容错加密兜底 (Fallback)**：
   - 若系统极简无桌面密钥环，自动切换为基于机器特征指纹 + 专用 Salt 派生的 `scryptSync` + `AES-256-GCM` 认证加密，保证磁盘无明文；
3. **磁盘原子化写盘**：
   - 加密凭据保存于 `userData/credentials/accounts.enc.json`，写入时先落盘临时文件再通过 `renameSync` 原子替换，防御进程崩溃损坏；
4. **IPC 严格脱敏隔离**：
   - 渲染进程通过 `credentials.list()` 仅可获取掩码数据（密码固定为 `••••••••`）；
   - 明文密码仅在受信任的单次自动填充链路中由主进程在内存按需解密，渲染端无法逆向拉取明文密码列表。

## 5. 进程安全模型

1. **上下文隔离**：所有窗口强制配置 `contextIsolation: true` 与 `nodeIntegration: false`；
2. **严格 CSP 策略**：渲染层严格限制 `connect-src` 到交大官方校内域名（`*.sjtu.edu.cn`、`*.tencentcos.cn` 等）；
3. **Webview 导航限制**：登录内嵌 Webview 设置严格域名白名单，防范点击未知外部链接逃逸；
4. **外部链接托管**：全局拦截窗口外跳，所有非应用内 URL 统一托管调用系统默认浏览器打开。
