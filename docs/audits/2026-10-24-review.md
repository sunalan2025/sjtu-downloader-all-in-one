### A02 · P1 · 独立 Worker 默认无鉴权，且允许访问任意 HTTP(S) 目标

位置：[scripts/private-worker-daemon.mjs](D:/SJTU/编程/sjtu-downloader-all-in-one/scripts/private-worker-daemon.mjs:22)、[scripts/private-worker-daemon.mjs](D:/SJTU/编程/sjtu-downloader-all-in-one/scripts/private-worker-daemon.mjs:598)、[scripts/private-worker-daemon.mjs](D:/SJTU/编程/sjtu-downloader-all-in-one/scripts/private-worker-daemon.mjs:673)、[scripts/private-worker-daemon.mjs](D:/SJTU/编程/sjtu-downloader-all-in-one/scripts/private-worker-daemon.mjs:786)、[scripts/private-worker-daemon.mjs](D:/SJTU/编程/sjtu-downloader-all-in-one/scripts/private-worker-daemon.mjs:861)。

Worker 监听 `0.0.0.0`，未配置 token 时直接放行。代理只检查 HTTP(S) 协议，下载入口也没有相同的目标限制；可访问回环/内网地址，且代理转发客户端 Cookie。下载根 `serverDownloadDir` 由请求指定，现有相对路径限制无法代替服务端固定输出根。

**影响前提：**访问者能够连接 Worker 端口。此时可使用服务端网络访问内网、消耗流量/磁盘，并在 Worker 账号拥有权限的目录内创建或覆盖文件。没有证明任意部署都可远程执行代码。

**证据：**默认配置的代理接受无鉴权请求，并尝试访问模拟的 `127.0.0.1` 服务，携带测试 Cookie。开发版 embedded worker 有域名限制，不能用其测试结果代表独立 daemon。

**建议：**默认仅监听回环并通过 SSH 使用；非回环监听必须配置强 token，否则启动失败。输出根由服务端配置并校验 realpath；按必要服务配置目标白名单，校验每次重定向和解析后的地址，按目标 origin 隔离 Cookie。不要在 query 中传 token。

**回归：**覆盖无 token、回环/IPv6/私网、重定向至私网、超出固定根、链接逃逸和跨源 Cookie。

### A03 · P1 · 登录自动填充使用子串判断，可能向非认证页面注入密码

位置：[src/renderer/src/pages/Login.tsx](D:/SJTU/编程/sjtu-downloader-all-in-one/src/renderer/src/pages/Login.tsx:564)、[src/renderer/src/pages/Login.tsx](D:/SJTU/编程/sjtu-downloader-all-in-one/src/renderer/src/pages/Login.tsx:1091)、[src/renderer/src/pages/Login.tsx](D:/SJTU/编程/sjtu-downloader-all-in-one/src/renderer/src/pages/Login.tsx:1148)、[src/renderer/src/pages/Login.tsx](D:/SJTU/编程/sjtu-downloader-all-in-one/src/renderer/src/pages/Login.tsx:1420)。

导航白名单只检查 SJTU 域名后缀，不检查 HTTPS；自动填充却使用 `url.includes('jaccount.sjtu.edu.cn')`。一个可控校园子域页面仅需在查询参数包含该字符串，就能同时满足两种判断。自动填充函数会读取保存密码并将其放进待执行脚本，函数内部和脚本内部没有最终 origin 守卫。账户切换还通过 console 消息触发，来源约束不足。

**影响前提：**攻击者能让登录 webview 到达可控的允许域页面，或利用导航切换时序。本次为静态调用链确认，没有使用真实凭据进行攻击实验。

**建议：**敏感注入必须严格匹配 `new URL(url).origin === 'https://jaccount.sjtu.edu.cn'`；执行前和脚本内部都检查。主进程在导航发生前实施规则，验证消息来源 frame；将敏感操作从任意 console 字符串通道迁移出去。

**回归：**查询参数含认证域、HTTP 页面、相似域、iframe、执行前后导航切换均不能取得或填入密码。

### A06 · P1 · Worker 缺少云盘 token 时仍报告上传完成

### A07 · P1 · Worker 未等待文件流完成，忽略背压，并绕过“跳过同名”

位置：[scripts/private-worker-daemon.mjs](D:/SJTU/编程/sjtu-downloader-all-in-one/scripts/private-worker-daemon.mjs:538)。

单文件分支直接 createWriteStream 覆盖目标；循环忽略 `write()` 的返回值；`end()` 后立即设置 completed，没有等 finish，也没有文件流 error 处理。慢盘可能积压内存，磁盘错误可能成为未处理事件，前端成功也不保证文件已完整写入。

**证据：**设置 skip 且模拟目标存在，仍发生写入；任务 completed 时 finish 尚未发生，error 监听器数量为 0。

**建议：**统一执行冲突策略；先写专用临时文件，用异步 pipeline/背压和 AbortSignal，等待写流完成并检查实际大小后再发布成品。错误须清理临时文件并进入 error。

**回归：**同名 skip/overwrite、慢写流、ENOSPC、权限错误、半途取消、截断响应。

### A08 · P1 · HLS 取消不传到底层，取消后又变成完成

位置：[src/main/download-engine/local.ts](D:/SJTU/编程/sjtu-downloader-all-in-one/src/main/download-engine/local.ts:157)、[src/main/download-engine/shared.ts](D:/SJTU/编程/sjtu-downloader-all-in-one/src/main/download-engine/shared.ts:201)、[src/main/canvas/hls-download.ts](D:/SJTU/编程/sjtu-downloader-all-in-one/src/main/canvas/hls-download.ts:583)。

HLS 路径没有注册正常下载使用的取消句柄，也没有向分片/转封装传入 AbortSignal。进度回调跳过 cancelled/paused 只是不再更新 UI，底层任务仍继续；await 返回后无状态检查便设置 done。暂停后重启还可能让两个任务争用同一输出。

**证据：**执行真实本地引擎的 HLS 分支，替换可控 HLS Promise，观察到 `downloading → cancelled → done`。

**建议：**把 signal 贯穿 playlist、分片、重试等待和 FFmpeg；取消终止子进程并收敛清理。每次 await 后验证任务版本/状态，旧执行实例不得覆盖新实例或终态。

**回归：**分片、重试等待、转封装各阶段取消/暂停；取消后不得继续下载、出现 done 或覆盖成品。

### A09 · P1 · 完成任务超过历史上限时，传输中心会持续更新状态

位置：[src/renderer/src/pages/TransferCenter.tsx](D:/SJTU/编程/sjtu-downloader-all-in-one/src/renderer/src/pages/TransferCenter.tsx:96)、[src/renderer/src/store/slices/download-slice.ts](D:/SJTU/编程/sjtu-downloader-all-in-one/src/renderer/src/store/slices/download-slice.ts:247)。

**建议：**只在任务进入终态时幂等写入历史，批量提交；初始化迁移也必须有独立的已处理标识。不要让组件依赖一个会裁剪的历史集合不断“补全”。

**回归：**299/300/301/1000 个完成任务，切换页面和重复终态事件；稳定后没有额外 store 写入。

### A10 · P1 · HLS 乱序缓冲无上限，少量线程也能缓存接近整段视频

位置：[src/main/canvas/hls-download.ts](D:/SJTU/编程/sjtu-downloader-all-in-one/src/main/canvas/hls-download.ts:209)、[src/main/canvas/hls-download.ts](D:/SJTU/编程/sjtu-downloader-all-in-one/src/main/canvas/hls-download.ts:244)。

`pendingWrites` 按序等待最早分片，空闲 worker 却持续领取后续分片。早期分片慢时，其余分片不断积压，内存上限接近总视频大小，并不由并发数限制。大量就绪数据还在主进程通过 writeSync 写盘。

**证据：**40 个分片、2 个 worker，阻塞第 0 片后，另外 39 片全部完成并等待落盘。

**建议：**按 writeIdx 设置滑动窗口与总字节预算，达到上限暂停领取；异步顺序写流，异常时停止其他 worker。大文件/慢盘处理可移出 Electron 主线程。

**回归：**首片慢、乱序、不同分片大小、慢盘和大视频；断言缓存字节数有界，并记录主进程事件循环延迟。
